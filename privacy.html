Privacy Policy

Last updated: 30 October 2026

Kriox is a prototype purchasing assistant operated by the Kriox project team ("we"). This policy explains what data Kriox handles, in particular the data it receives from Google when a Gmail account is connected, and what we do with it. For questions write to watund3@gmail.com.

1. Who uses Kriox

Kriox has no public sign-up. Its users are the staff accounts created by the project team (for example a warehouse clerk, a buyer or a plant manager) and, indirectly, the suppliers who exchange e-mail with the system. The Gmail connection is made once, by the owner of one Gmail account, for the whole system.

2. Google user data we access

When the Gmail account owner connects the account, Kriox asks for one scope: https://www.googleapis.com/auth/gmail.modify. Kriox uses it for these actions only:

  • Read new messages that arrive in the inbox. Kriox downloads each new message to see who it was addressed to.
  • Keep only messages addressed to Kriox's own reply address (a plus-address of the connected account, such as name+grv@gmail.com). Every other message is dropped from memory as soon as this check fails: it is not stored, analysed or shown to anyone.
  • Label each message that Kriox kept with the label GRV-processed, so it is not read twice. This is why a scope that allows changing labels is needed.

Kriox does not send mail through the Gmail API, does not delete mail, does not change any message other than adding that label, and does not read contacts, calendar, Drive or any other Google data. Outgoing mail is sent through Amazon Simple Email Service.

If Google sign-in is switched on for the web application, Kriox also receives the signing-in user's name and e-mail address (scopes openid email profile) to identify them. A person signing in this way has no access to any case until an administrator gives them a role.

3. What we do with kept messages

For each kept message Kriox stores the sender, subject, body and attachments, links them to the purchase order or price request the message answers, and shows them to the staff responsible for that case. To understand a reply (for example to tell a price quote from a refusal, or to read a delivery date), the text and attachments are processed by:

  • AI language models: Anthropic Claude through SAP AI Core, and Anthropic Claude on Amazon Bedrock as a fallback;
  • Amazon Bedrock Guardrails, which screen the message for unsafe or manipulative content;
  • Amazon Textract, which reads text from attached documents and photographs.

The model output is a suggestion. A named staff member approves or rejects each consequential step, and every step is recorded in an audit trail.

4. Limited Use

Kriox's use and transfer of information received from Google APIs to any other app will adhere to the Google API Services User Data Policy, including the Limited Use requirements. In particular:

  • We use Google user data only to provide the supplier-reply feature described above.
  • We do not sell Google user data and do not use it for advertising, profiling or marketing.
  • We do not use Google user data to train, fine-tune or evaluate generalised AI models.
  • We do not transfer Google user data to others, except to the processors listed in section 3 as needed to provide the feature, to comply with law, or with the user's consent.
  • Humans do not read Google user data except the staff responsible for the case a message belongs to, to investigate abuse or a security problem, or where the law requires it.

5. Where data is stored and for how long

Data is stored in Amazon Web Services in the Asia Pacific (Sydney) region (ap-southeast-2): case and audit records in Amazon DynamoDB, attachments in an encrypted, non-public Amazon S3 bucket, and the Gmail access credentials (a refresh token and the OAuth client secret) in AWS Secrets Manager. Traffic uses HTTPS. Application logs are kept for 30 days.

The prototype has no automatic deletion schedule for case records. We delete the stored copy of a message on request (section 7) and when the system is reset or shut down.

6. Other information

  • Staff accounts: user name, e-mail address, role and password, held by Amazon Cognito.
  • Telegram: if a user or supplier links a Telegram chat, Kriox stores the chat identifier and the messages and photos exchanged with the bot.
  • Cookies: the web application uses no advertising or analytics cookies.

7. Your choices and rights

  • Revoke Gmail access at any time at myaccount.google.com/permissions. Kriox then stops reading the inbox; the stored token no longer works.
  • Ask for access or deletion of data that came from your messages by writing to watund3@gmail.com. We answer within 30 days.

8. Security

Access is limited by role, secrets are held in AWS Secrets Manager, S3 buckets are not public, and actions are written to an audit trail. No prototype is free of risk; do not send information to Kriox that you would not want processed as described here.

9. Children

Kriox is a business tool and is not directed to children.

10. Changes

If this policy changes, we change the date above. A change that widens what we do with Google user data will be shown here before it takes effect.
